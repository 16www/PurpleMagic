# 角色等级与成长

角色资料的“等级与成长”页签支持1–90级调整。预览展示等级、累计经验、SP/TP及24项基础属性的变化，提交后保存永久回执与分页记录。页面按打开、手动刷新和操作结果读取，空闲时不轮询。

## 成长规则

- 经验使用当前游戏的累计值：目标1级为0，其他等级取PVF `character/ExpTable.tbl` 中上一等级的升级阈值。本次调整将经验放到目标等级起点。
- 基础属性按当前职业、转职/觉醒和目标等级计算，复用游戏 `charstat` 算法与HP/MP兼容加值。正负抗性按PVF原值写入。
- SP/TP总量为目标等级PVF累计点数加原额外点数；保留已消耗点数。总量超过65535或低于已消耗点数时拒绝。
- 职业、转职/觉醒、任务、装备、额外点数、已学技能和快捷栏保持。本次操作只改成长字段；进场后仍执行游戏已有的技能同步规则。

等级下降与上升使用同一预览和事务。角色已有多少点数被消耗，会影响可调整到的等级；技能重置与转职另按各自功能处理。

## API

| 方法与路径（前缀 `/api/v1`） | 内容 |
| --- | --- |
| `GET /characters/{id}/level` | 当前等级、经验、点数、基础属性、PVF定义和revision |
| `POST /characters/{id}/level-operations/preview` | 计算前后值、返回定义版本和有效十分钟的签名 |
| `POST /characters/{id}/level-operations` | 提交并返回永久回执 |
| `GET /characters/{id}/level-operations?limit=10&cursor=...` | 独立分页记录 |

预览请求：

```json
{"accountId":"<账号ID>","targetLevel":85,"revision":"<角色成长与技能账本版本>","pvfChecksum":"<完整PVF SHA256>","reason":"等级调整"}
```

提交使用原请求加预览返回的 `definitionRevision` 与 `planToken`，携带会话、`X-CSRF-Token` 和 `Idempotency-Key`。签名绑定角色、账号、目标等级、原因、操作者、原状态、PVF及目标定义。相同请求在响应丢失后返回原回执；恢复时先读永久回执，无需PVF和在线接口。

## 数据与缓存

读取有界投影包含角色身份/等级/职业、31个相关属性键及技能点账本，使用一致性快照。事务先锁角色、再锁技能父行，然后读取附属字段；游戏的技能或成长事务先完成时，旧预览返回冲突。

写入定点更新等级、累计经验、24项基础属性、技能点及时间、`gm_level_sequence_v1`和独立回执。保留其他角色列、负数哨兵、点券/金币、技能等级、快捷栏、冷却及其他角色数据。默认读权威列；旧镜像模式遵循补充表优先、列回退并同步已有影子的规则。

回执表为 `<前缀>_level_management_operations`，升级时执行已有 `--init-management-schema`；正常启动检查表结构。

静态定义读取经验表、点数表、职业列表和列表中的职业文件，缓存解析后的小表，不加载完整PVF或技能目录。按完整PVF摘要换代，预览同时绑定解析版本和目标计算结果。

## 验证与运行接入

`TestV1LevelMySQL` 覆盖单/双分片、旧镜像、升降级、累计经验、字段保持、负抗性、并发幂等、失败回滚、真实游戏成长锁等待、技能点操作冲突、签名与PVF换代、失联恢复及分页。`scripts/verify_gateway_level.py` 使用实际网关、真实PVF和一次性数据库验证网页、恢复、资料一致性及手机布局。

提交前后核对离线状态；游戏侧跨进程编辑锁仍是上线前置项。当前接口未接入真实玩家环境。
