# 游戏任务操作

在“账号与角色”打开角色后，“游戏任务”查看当前记录，“任务库”搜索 PVF 定义。选择任务、填写原因并预览，核对逐条变化后提交。“任务操作记录”按角色分页显示回执及前后状态。

| 操作 | 行为 |
| --- | --- |
| 接取任务 | 按现有领域规则校验等级、职业、前置与冲突，保留已接取任务的幂等语义 |
| 放弃任务 | 按 PVF 的可放弃条件删除任务状态 |
| 标记可交 | 将已接任务的目标进度设为 0，保留任务元数据；已有奖励结算记录时返回冲突 |
| 标记完成（不发奖励） | 归档任务，保留既有结算证据，记录无奖励完成；普通游戏交付不能再次领取这次奖励 |
| 恢复未完成 / 重置链路 | 普通已完成任务删除状态；受管理的父子任务按领域规则整族重置并重新激活，预览列出关联变化 |

网页支持选择当前页任务，接口每批最多 200 个不同任务。批次在同一事务完成；失败时返回具体任务编号，整批回滚。重复选择同一链路的父子任务只重置一次。职业变更任务和需要接取发物品／放弃回收物品的任务继续通过专用流程处理。

## API

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/v1/characters/{id}/quest-operations/preview` | 查询实际状态并生成变更预览；不保存任务或回执 |
| `POST /api/v1/characters/{id}/quest-operations` | 提交并取得持久回执 |
| `GET /api/v1/characters/{id}/quest-operations?limit=20&cursor=...` | 分页操作记录，游标绑定角色、账号与查询条件 |

请求示例：

```json
{
  "accountId": "<角色所属账号>",
  "action": "complete",
  "questIds": ["1", "2"],
  "reason": "修复任务进度",
  "revision": "<预览返回的版本>",
  "pvfChecksum": "<预览返回的完整 PVF SHA256>"
}
```

`action` 为 `accept`、`give-up`、`ready`、`complete`、`reset`。预览请求省略 `revision`、`pvfChecksum`。所有请求使用管理会话；POST 携带 `X-CSRF-Token`，提交另带 `Idempotency-Key`。角色和任务 ID 使用规范十进制字符串。

角色行锁内重验归属、删除状态、角色资格与完整任务版本。任务状态和永久回执同事务提交；流水保存失败、版本冲突或在线检查失败均回滚。预览版本绑定 PVF 摘要，新的操作不能继续使用旧代次。任务定义及关联任务从离线索引按记录读取。

相同请求编号与内容返回原回执。已提交请求的恢复先读取回执，再判断是否需要当前 PVF 或游戏接口，因此 PVF 更新、游戏接口暂不可用不影响取回既有结果。浏览器将待确认编号与原请求保留在当前标签页的会话存储中，刷新后可继续重试。

## 安装与验证状态

新增角色级管理回执表，沿用显式安装入口：

```text
PlayerGateway --config gateway.json --init-management-schema
```

当前提交会在数据库事务内、保存任务前后查询游戏私有接口的角色在线状态。上线前还需接入游戏端跨进程编辑锁，覆盖离线检查之后角色立即登录的竞争窗口。

本地验证覆盖单／双分片 MariaDB、同键并发、不同键版本竞争、失败回滚、持久回执恢复、关联任务重置与普通奖励防重；实际网关和独立网页验证预览、可交、无奖励完成、恢复未完成、操作记录、响应丢失后刷新恢复、主题与移动布局。浏览器预览的游戏在线接口由隔离示例运行时提供，游戏原生交互验收安排在上线阶段。

```text
python gateway/scripts/test_mysql.py
python scripts/verify_gateway_quests.py
```
