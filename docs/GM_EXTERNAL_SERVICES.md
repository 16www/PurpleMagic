# 外部 GM 与游戏侧网关

`gateway/cmd/gmservice` 承载 GM Web、管理员会话、PVF 索引、静态检索、邮件队列和福利调度。`playergateway` 的外部管理模式保留玩家查询、领域事务、游戏准入检查和永久回执。

| 外部 GM 服务 | 游戏侧单网关 |
| --- | --- |
| GM Key 登录、Cookie、CSRF | 独立服务凭据与固定 v1 操作 |
| 批准 PVF、六类索引和静态物品／任务检索 | 512 条有界物品摘要缓存、按需任务及职业定义 |
| 成长、物品参数、邮件奖励定义计算 | 目标归属、数据 revision、预览身份、事务与回执 |
| 已确认邮件的持久队列、福利定时调度 | 每批最多10封邮件、每次最多5个账号的福利扫描 |
| 网页关闭后继续运行，重启后恢复 | 原规则 ID、受众截止时间和发放回执 |

外部配置没有玩家数据库字段。服务链路只传类型化定义与有界领域请求；静态物品和任务检索直接在外部完成。游戏侧外部模式不会打开 PVF、完整索引或启动本地福利定时器。

## 发放与恢复

选择账号表示其全部现有角色，和显式角色名单合并去重。准备名单时固定收件人，确认框显示完整名单。外部客户端调用 `POST /api/v1/tasks/{id}/schedule`，队列先持久保存确认，再调用游戏网关的既有批次接口。

任务查询增加 `schedule`：`active`、`paused`、`completed` 或 `conflict`。`POST /api/v1/tasks/{id}/pause` 在当前批次结束后暂停。页面仅在查看运行中任务时读取进度。关闭页面后继续发放，重新打开任务即可查看或暂停。

队列在请求前保存 `inFlight` 和 revision。响应丢失或服务重启时先读取权威任务：已提交批次从新 revision 继续，未提交批次以原 revision 重试。最终去重依赖数据库永久回执。规则修改、目标归属或 PVF 冲突继续使用原领域校验。

福利启用后由外部定时器调用私有扫描接口。游戏侧保存原规则和回执，串行处理有界账号范围；已有角色截止时间与未来角色选项分别生效。

## PVF 代次与服务身份

服务配置固定批准 PVF 的完整 SHA256。启动时重新计算文件摘要并验证索引代次；内容改变后重新生成和验证索引，再切换两端配置。文件路径、大小和修改时间不作为代次身份。

私有链路同时核对服务凭据、`purplemagic-service-v1` 和 PVF 完整摘要。凭据保存在配置文件，浏览器只持有管理员会话。私有接口拒绝浏览器 Cookie／Origin，客户端禁止重定向。链路使用 TLS 或 loopback 上的 SSH 转发。

外部定义接口只接受指定操作，如物品摘要、任务定义、职业、成长、金库及奖励投影；没有任意文件读取接口。成长和职业等操作继续核对领域定义版本、目标身份、数据 revision 与预览签名。

## 运行与切换

1. 用 `gmservice -config <protected-config.json>` 运行外部服务；网页和定义接口分别绑定 loopback 监听。配置 `queuePath`、批准资产路径、管理 Key 摘要、服务凭据、游戏网关地址及扫描周期。
2. 游戏侧 management 配置增加 `catalog`（`url`、`token`、`pvfSha256`，TLS 可指定 `caFile`／`serverName`）及 `serviceToken`。原数据库、游戏私有 API 和回执表继续沿用。
3. 先部署游戏角色准入协议，再停旧网关扫描并切换外部模式，最后启用外部扫描。两端读取同一 PVF 代次。
4. 回退时先停外部调度并等待在途请求，再恢复旧应用与入口，继续使用当前数据库和回执。

## 验证

单元测试覆盖服务鉴权、跨站隔离、PVF 代次不符、静态检索零游戏侧请求、定义传输一致、断网拒绝、队列响应丢失／重启恢复、暂停和旧代次停止。一次性 MariaDB 与浏览器覆盖账号展开、重复请求、15人多批投递、关闭页面继续、自动福利和角色工作区。真实批准 PVF 用于物品、任务、成长、职业、副职业与金库定义对照。
