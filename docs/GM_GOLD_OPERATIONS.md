# 角色金币管理

角色资料的“金币与流水”页签支持增加、扣减和设置目标金币。每次操作先读取当前余额，再由网关生成变更预览，确认后保存金币与永久回执。页面按打开、翻页和显式刷新查询，静置时不发送请求。

## 金币契约

角色金币对应角色存档的 `Stats["gold"]`，MySQL 权威列为 `characters.gold`。当前客户端的钱包回包支持 `0..2147483647`，增加或扣减数量须大于零，设置目标余额允许零。金额在 JSON 中使用十进制字符串，拒绝负数、前导零、小数和溢出。

账号点券 `account_cera`、账号金库金币 `account_cargo_gold` 和携带金币购买阶段 `carry_gold_stage` 分别管理。本操作只改变角色金币，保留这些字段及其他角色属性。

## 接口

| 方法与路径 | 内容 |
| --- | --- |
| `GET /api/v1/characters/{id}/gold` | 当前金币、上限、账号归属与版本 |
| `POST /api/v1/characters/{id}/gold-operations/preview` | 计算变更前后值，返回签名预览 |
| `POST /api/v1/characters/{id}/gold-operations` | 提交原预览与请求编号，返回回执 |
| `GET /api/v1/characters/{id}/gold-operations?limit=10&cursor=...` | 分页 GM 金币流水 |

预览请求：

```json
{
  "accountId": "example:1",
  "action": "add",
  "amount": "100000",
  "revision": "<GET 返回的版本>",
  "reason": "活动金币补偿"
}
```

`action` 取 `add`、`subtract` 或 `set`。预览返回 `receipt` 和 `planToken`；提交在原请求中加入 `planToken`，并带 `Idempotency-Key`。两个 POST 均要求会话与 CSRF 校验。预览有效期十分钟，绑定账号、角色、操作、金额、原因、版本和管理员身份。

回执记录 `before`、`after`、有符号 `delta`、操作金额、原因、操作者、时间与请求编号。读取流水只包含 GM 金币操作；游戏消费和奖励日志沿用游戏业务记录。

## 数据访问与事务

余额查询只选角色标识、账号、金币、删除标记、更新时间和一个管理版本键；不加载背包、任务、位置或整组属性。预览与提交共用角色行锁和归属检查；写入仅更新 `gold`、`updated_at` 和 `gm_gold_sequence_v1`，回执保存在同分片的 `character_gold_operations`。管理表由显式初始化命令创建，服务启动检查表结构。

提交检查读取版本与余额范围，先后核对角色在线状态，并在保存后读回金币和版本。金币、版本与回执同事务提交，任一步失败全部回滚。重复请求返回原回执，同编号不同内容返回冲突。已完成请求可在预览过期或游戏状态接口不可用时恢复。

角色离线检查当前使用游戏接口的前后采样。上线前继续接入游戏端跨进程编辑锁，覆盖检查后登录的竞争；原生客户端重新进场的显示验收列入第五阶段。

## 验证

`gateway/scripts/test_mysql.py` 在一次性 MariaDB 中覆盖单／双分片：预览零写、定点字段保留、同键并发重放、不同键版本冲突、余额边界、保存/回执失败回滚、后置在线变化回滚、签名预览、过期、CSRF、分页与币种隔离。包含旧 mirror 配置的查询与写入一致性。

`scripts/verify_gateway_gold.py` 使用实际网关与独立 Web 验证增减、设置上限/零、响应丢失后刷新恢复、另一管理员修改后的冲突、角色/账号隔离、流水、主题、移动布局与静置零请求。
