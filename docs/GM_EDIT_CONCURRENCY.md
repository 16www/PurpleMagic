# GM 编辑与游戏登录

2026-10-18 候选按实际资产归属选择占用范围。角色背包、个人仓库、穿戴／宠物、任务、金币、容量、技能点、等级、职业、副职业和邮箱清理只要求目标角色返回选角界面并完成清理；同账号其他角色不阻断。账号金库及共享晶块／灵魂仍要求账号退出游戏连接，包含选角界面。账号点券和普通邮件投递继续使用各自的权威事务。

## 提交顺序

1. 网关开启数据库事务，先锁定权威 `accounts.account_id` 行，再锁定操作所需的角色或容器行。
2. 已存在的永久回执直接返回；新的提交按归属查询 `character_edit_status` 或 `account_edit_status`。
3. 角色响应包含 `character-admission-v1`、完整账号／角色身份及是否占用，目标角色正在选角、在线或尚在清理均视为占用。账号共享资产继续使用 `account-row-v1`，账号登录、选角界面及清理阶段均视为占用。
4. 网关在修改前和提交回执前分别核对状态，数据和回执在同一事务提交。

游戏在绑定启动令牌、读取账号和角色数据前登记账号占用，然后通过独立事务等待同一账号行锁。GM 若先完成最后一次状态检查，登录会等待提交后再读数据；登录若先登记占用，GM 会回滚。事务提交、回滚或连接断开由数据库释放锁，无需过期计时器。

角色选角在读取完整目标角色前也登记占用，等待同一账号行锁，然后重新读取角色、核对身份／归属／槽位／删除标记。选角失败保持占用，返回选角完成角色清理后释放角色登记。账号行锁继续保留，缩小的是占用判断范围。

一个账号的多条游戏连接分别登记。角色解绑和频道交接保留登记，只有会话清理完成且事件循环停止后才删除。清理超时的账号保持占用并记录错误，完成清理或重启游戏服务后恢复。新游戏进程同样等待已有数据库事务。

## 接口与运行范围

私有 `POST /api/game/admin` 使用独立服务凭据。角色动作：

```json
{"version":1,"action":"character_edit_status","accountId":"example:1","characterId":10}
```

```json
{"version":1,"ok":true,"characterEdit":{"protocol":"character-admission-v1","accountId":"example:1","characterId":10,"busy":false}}
```

原账号动作继续保留：

```json
{"version":1,"action":"account_edit_status","accountId":"example:1"}
```

```json
{"version":1,"ok":true,"online":false,"accountEdit":{"protocol":"account-row-v1","accountId":"example:1","busy":false}}
```

账号由管理事务验证归属。游戏使用严格启动令牌认证及 MySQL 账号仓储时提供此能力。缺少能力、服务失联、协议或返回账号不匹配时，新编辑返回 `runtime_unavailable`；已有回执仍可恢复。

当前契约对应一套数据库及承载全部频道的一个游戏进程。多游戏进程共享账号时，需要先实现跨进程会话占用汇总。管理监听和凭据继续与公开玩家入口分离。

`online_snapshot` 仍提供角色级在线名单，供在线范围邮件固定收件人；编辑占用证明与角色在线名单分别使用，普通在线快照不能替代编辑证明。

## 切换

角色准入补丁位于独立游戏候选，须整合到届时真实累计源码并验证；先上线兼容的新游戏协议，再启用本轮网关和GM Web。旧游戏不提供角色证明时，新角色编辑会拒绝。回滚应用版本不回滚已提交的资产或回执。管理回执表使用追加建表，保留旧福利规则身份和永久回执。上线核对批准 PVF 的完整摘要及离线索引代次，分别记录游戏、网关和 GM Web 的源码与产物摘要。

本次私有接口变更不修改客户端报文或要求新 EXE。后续依赖 EXE 的服务端变更仍执行项目的 EXE Release、实际玩家源和配套资源验哈门槛。
