# 实验性玩家资料公开快照

状态：第四阶段新增需求与接口设计。用于向外部网页或服务提供角色背包、穿戴装备、通关时长和通关记录，供玩家查询比较。接口实现安排在背包只读投影与通关记录采集之后。

## 已确认的行为

- 公开范围可切换为 GM 指定角色名单，或全部角色。全量模式在后续刷新时自动纳入新建角色。
- 外部接口只读已发布快照。后台刷新优先级很低，默认每日一次，时间与频率可配置。
- 外部访问频率与游戏数据库读取频率分离；刷新由 GM 调度。

## 公开范围

配置拟为 `enabled`、`mode: allowlist | all`、`characterRefs`、`refreshInterval`、`refreshAt`、`revision`。

初始状态为关闭、空名单。管理员启用后选择名单或全量模式。名单保存角色稳定标识与创建代次；同名角色、删角重建分别识别。全量模式下新角色在下一次成功刷新后出现。切换范围时递增 `revision`，发布中的任务须复核对应版本。

所有列表、详情、背包和记录端点使用同一可见范围。缩小名单、删除角色或关闭发布后，源站立即停止提供对应内容，淘汰相关页面缓存；正在生成的旧范围快照停止发布。外部分发缓存采用短期可重验证策略，并支持失效通知。

## 后台生成与存储

GM 使用低优先级单任务队列，逐页枚举角色并逐角色生成投影；配置每批数量、读取超时、批间隔、单轮时间预算与磁盘配额。正常 GM 操作、福利发放和游戏负载优先。预算用尽时保存进度，后续继续。

每个角色以一次只读一致性读取取得基础资料、背包与穿戴装备。适配器明确列出读取字段，检查现有仓储加载路径是否有迁移或回写副作用。生成阶段使用现有 PVF 名称索引补充物品名称。

快照存为分角色、分记录页的磁盘文件，目录清单有界分页；只读服务按页读取，并限制响应字节数和缓存容量。生成新版本后原子切换清单，保留最近成功版本；失败保存原因与进度。公开请求不会触发补抓或重建。

角色背包记录带各自的 `observedAt`。通关记录带采集覆盖窗口和完整性。一天一次适用于公开快照生成，通关事件在游戏权威提交点持续记录，随后供每日汇总读取。

## 公开字段

| 数据 | 字段 |
| --- | --- |
| 角色 | 独立 `publicId`、角色名、职业、等级 |
| 物品 | 槽位、物品 ID/名称、数量、绑定状态；已核验的强化/增幅/锻造/附魔展示字段 |
| 穿戴 | 装备槽位及与背包一致的物品投影 |
| 通关 | 公开记录 ID、副本/难度、开始/完成时间、服务端耗时、单人/组队及人数、结果与完整性 |
| 快照 | schemaVersion、snapshotId、policyRevision、publishedAt、observedAt、recordsThrough、freshness |

身份和物品 ID 使用字符串，时间使用 UTC RFC3339，耗时单位为毫秒。公开模型采用字段白名单；账号登录名、IP、设备标识、鉴权信息、邮件、余额、账号仓库、原始二进制和任意 Extra 字段留在管理侧。

背包快照与通关记录分别标注时间。以后若采集入场装备，可另提供该局装备快照。通关时长取服务端计时；缺失起点、终点或事件的记录使用空耗时与明确完整性状态。异常核查与封禁仍属于管理功能。

## 公开接口草案

前缀为 `/public/v1`，只读适配器仅持有快照存储。GM 管理接口、数据库连接和游戏私有 API 保留原访问边界。外部服务器可同步公开快照副本，再由同一只读契约提供查询。

| 方法与路径 | 返回 |
| --- | --- |
| `GET /public/v1/snapshot` | 当前公开版本、发布时间、刷新周期、数据覆盖窗口与状态 |
| `GET /public/v1/characters?q=&limit=&cursor=` | 当前公开角色目录 |
| `GET /public/v1/characters/{publicId}` | 单角色公开资料与各数据更新时间 |
| `GET /public/v1/characters/{publicId}/inventory?limit=&cursor=` | 背包与穿戴投影分页 |
| `GET /public/v1/characters/{publicId}/dungeon-runs?limit=&cursor=` | 按完成时间排序的通关记录分页 |

分页默认 20、上限 100；游标绑定快照版本、公开策略版本与查询条件。版本更换后过期游标返回具名错误，调用方重新从第一页读取。ETag 同时包含快照与策略版本；静态缓存命中支持 304。发布缓存的具体 TTL 与失效机制在部署时统一配置。

未知或未公开角色返回 404；尚无成功快照返回 503。有历史成功快照时返回原数据及 `freshness: stale`、原采集时间。未采集通关记录与“已采集但没有记录”使用不同状态。

接口设请求速率、并发、分页和响应大小上限。网页跨域读取可配置允许的来源；公开 GET 不携带 GM Cookie。刷新、选名单和切换全量模式属于已认证的管理操作。

## 已核验的数据来源

- GM `InventoryRecord` 包含角色 Slots、Warehouse、UpdatedAt；`EquipmentRecord` 包含 Entries。公开投影选择角色背包和穿戴字段。
- 游戏已有 `runtimeDungeonState.startedAt`、`clearMapCompletionAt`，以及 `currentDungeonSettlementElapsedMilliseconds` 的服务端耗时计算。当前代码可作为计时语义依据。
- 现有运行时计时与任务完成回执尚未提供完整通关历史查询。先补版本化通关事件与持久记录，再向公开快照投影；历史覆盖起点据实记录。

## 实施与验收

1. 新版 GM 接入背包只读查询与游戏通关记录采集。
2. 实现名单/全量两种策略、低优先级生成器及磁盘快照；确认全量模式新增角色、删角重建和策略变更行为。
3. 实现快照只读端点与外部服务示例，验证重复访问产生零游戏数据库查询、零自动刷新任务。
4. 验证刷新中断、超时、重启恢复、磁盘配额、旧快照服务、策略收缩、缓存失效及公开字段白名单。
5. 在目标数据量下测量刷新耗时、数据库读取量、GM 峰值内存与外部高频读取资源，再纳入第五阶段联调。
