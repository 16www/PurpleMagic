# 独立 GM 客户端与轻量管理网关

本文保留早期目标设计。2026-10-17实际源码架构见[当前全局架构](ARCHITECTURE.md)和[基础设施](FOUNDATIONS.md)。Key登录已经实现；客户端PVF分片/IndexedDB、通用作业队列与多层玩家缓存尚未实现，以下目标描述不作为当前完成状态。

本项目调整为“一个服务端网关、多种独立客户端”。GM 首先提供 Web/PWA，后续安卓或其他管理客户端复用同一套管理 API。除现有游戏服务与 MariaDB 外，工具链部署一个网关进程，包含玩家入口、更新 Hub 与管理模块。

2026-10-17 已完成首批迁移：`gateway/` 可在单进程提供玩家入口、Hub 与 GM v1 API，`gm-web/` 为独立静态客户端。账号点券增减与流水已接入；原 `gm/` 保留离线索引工具与迁移来源。下文描述完整目标边界，当前实现和验证见 [本轮实现](GM_GATEWAY_IMPLEMENTATION.md)。

## 职责与部署

| 组件 | 职责 | 常驻内容 |
| --- | --- | --- |
| 独立 GM Web/PWA | 玩家检索、管理表单、预览结果、主题、物品/任务检索 | 浏览器按需缓存目录分片和详情 |
| 网关管理模块 | 认证授权、查询、业务操作、事务、幂等、回执、作业与审计 | 有界请求缓存、连接池、轻量目录元信息和有限作业状态 |
| 网关玩家入口 / Hub | 玩家登录转发、签名更新、资源传输、公告 | 现有发布元信息和有界传输状态 |
| 现有游戏服务 | 在线会话、玩法规则、任务奖励结算、实时更新与事件产生 | 游戏自身运行状态 |
| 现有 MariaDB | 玩家存档、管理配置、操作回执、作业及采集记录 | 持久数据 |
| 离线 PVF 工具 | 从批准 PVF 生成展示目录与操作校验数据 | 构建期间占用，结束后释放 |

GM Web 作为独立静态包发布，可选由网关提供这些静态文件，也可在配置的管理站点托管。独立发布不要求另开一个 Node 或 Go 后端。首次优先同源部署，减少跨域与浏览器私网访问差异；跨源模式单独配置精确来源并验证 Cookie/CSRF/预检策略。

同一个网关进程保留玩家监听与管理监听的分离。玩家监听沿用现有白名单；GM API 注册在管理监听，使用独立身份、权限及请求额度。移动端通过明确配置的管理网络入口访问。菜单由能力和权限决定，授权在每个请求执行时复核。

## 接口表达业务操作

接口使用版本化资源和动作，客户端提交账号、角色、物品、操作类型和参数，网关负责存储映射。SQL、表名、列名及数据库凭据属于服务端实现。

第一批保留现有 `/api/v1` 的读取响应和分页约定，逐步补写入契约：

| 接口示例 | 行为 |
| --- | --- |
| `GET /api/v1/capabilities` | API/数据格式版本、已实现能力、权限、当前 PVF 代次 |
| `GET /api/v1/accounts`、`/characters` | 按条件查询基础资料，游标分页 |
| `GET /api/v1/characters/{id}/inventory` | 按容器查询真实槽位；模板显示信息由目录提供 |
| `POST /api/v1/accounts/{id}/currency-adjustments` | 指定币种、增减量、原因、预期版本；账号事务内更新并生成回执 |
| `POST /api/v1/characters/{id}/inventory/operations` | 修改/删除选中实例，核对槽位、实例版本、当前规则和归属 |
| `GET /api/v1/characters/{id}/quests` | 玩家任务状态，与静态任务定义组合显示 |
| `POST /api/v1/characters/{id}/quest-operations` | 接取、放弃、标记可交、标记完成等明确动作 |
| `GET /api/v1/operations/{id}` | 查询操作状态、前后值、失败原因和回执 |
| `GET /api/v1/catalog/manifest` | 当前批准 PVF 对应的展示目录与规则索引版本 |
| `GET /api/v1/catalog/...` | 按摘要、分类或 ID 范围读取不可变分片/单件详情 |

表中新增写路径为设计契约，尚未注册到当前服务。OpenAPI 与独立于页面的契约测试先于迁移实现建立；各终端使用相同请求格式，隐藏菜单不替代服务端权限判断。

查询继续使用字符串 ID、具名错误、读取时刻、请求 ID、游标与超时。写入使用持久幂等键、目标 revision 和原因。相同请求重放返回原结果；相同键不同内容拒绝。预览只表达当时结果，执行时仍在事务内读取当前状态。回执及资产改变在同一事务提交，提交后使相关视图失效。

跨游戏进程的操作使用操作 ID、可查询回执及重试协议；网络超时记为结果待核实，不凭超时再次发奖。在线背包、金币等由游戏命令入口完成内存状态与持久化的一致更新。离线直接修改需要覆盖写入期间的登录/会话协调，当前一次性离线探测不足以构成该机制。

“标记任务完成”与“完成任务并结算奖励”使用不同动作；后者复用游戏权威结算。点券归属账号，金币和物品归属按实际存储契约区分。

## PVF 分工

离线工具生成一份版本清单和两类索引：

1. **展示目录**：物品/任务 ID、名称、分类、检索信息、详细描述与套装等。按分类、ID 范围及详情拆分，浏览器首次只取清单和所需分片，使用 IndexedDB/Cache Storage 缓存；安卓可以采用本地数据库。
2. **操作校验索引**：物品存在性、类型、可堆叠数量、装备参数范围、任务关联与操作所需字段。保存在网关磁盘，按记录读取，使用明确字节上限的热点缓存。需要完整游戏状态或复杂玩法规则时调用游戏服务。

服务端以自己配置的批准 PVF 代次及校验索引为准。客户端显示的名称、类型或上限不作为写入依据。写请求携带观察到的目录代次，代次不符时重新读取和预览。

索引身份包含完整 PVF SHA256、数据格式版本和解析器版本。清单列出每个分片的摘要与大小，由已认证管理连接提供；内容地址本身不赋予操作权限。构建在临时目录进行，逐项校验后发布清单；旧版本保留到在途请求结束，磁盘配额和回收策略单独控制。

生产网关只消费完整、匹配的索引包；索引缺失时对应功能报告未就绪。全量 PVF 解析放在独立命令中运行，工具可在管理员工作站构建。网关查询不触发整份 PVF 解析或目录构建。

物品搜索以客户端已缓存的目录分片为主；服务端提供按需检索能力以支持薄客户端，使用磁盘检索结构和有界结果。独立 Web 包无需启动时加载全部物品说明或整个 PVF。

## 缓存和后台任务

| 数据 | 读取策略 | 更新与释放 |
| --- | --- | --- |
| PVF 展示数据 | 客户端按需缓存不可变分片 | 新代次新命名空间；旧代按本地配额回收 |
| 操作校验记录 | 网关磁盘随机读，有限热点缓存 | 按 PVF 代次隔离，整体预算控制 |
| 玩家当前资料 | SQL 分页；同目标在途合并及短时缓存按需启用 | 操作提交后按账号/角色/容器失效；强制刷新绕过缓存 |
| 在线状态及写入资格 | 游戏接口与事务中的权威读取 | 界面可以短时展示，执行不依赖展示缓存 |
| 通关历史与统计 | 有界批量采集、分页和预聚合 | 保存期限、索引及归档配额 |
| 公开玩家资料 | 每日低优先级生成磁盘快照 | 原子切换清单；公开请求只读已发布快照 |

后台福利、批量发放和公开快照在客户端关闭后继续运行。网关采用数据库持久作业和少量 worker；每批限定条数、时长和并发，恢复时依据永久回执重放。网关实例并发运行时使用领取租约和事务去重。初版复用现有 MariaDB，不引入额外缓存或队列服务。

数据库连接按逻辑数据库集中装配并设总上限，管理作业、资源下载与普通读取分别限制并发，避免大文件传输耗尽管理额度。缓存按字节与条目双重限制；新增菜单默认不新增常驻扫描器。

## 登录与多端

统一身份模型提供操作者、权限范围、凭据编号、有效期及撤销。用户此前询问的登录 key 文件可作为管理凭据的导入载体，包含管理地址和专用登录凭据；服务端保存摘要，登录后签发有期限的会话。该功能尚待实现。

Web 使用 HttpOnly 会话 Cookie 和 CSRF 校验；安卓等原生客户端使用有期限的访问凭据及系统安全存储。各自的退出、撤销、来源规则和刷新策略列入认证契约。数据库密码、Hub 发布凭据和签名私钥保留在服务端配置，不放入 GM 静态包或登录 key 文件。

## 代码迁移

目标目录仅表达职责，尚未执行源码搬迁：

```text
gateway/
  cmd/gateway/              # 唯一常驻进程的装配
  cmd/pvf-index/            # 独立离线构建命令
  internal/management/      # API、身份、操作、作业、审计
  internal/modules/dnf/     # 迁入并固定来源的领域规则及仓储契约
  internal/platform/       # MariaDB 适配、磁盘索引及有界缓存
  internal/services/launcherhub/
gm-web/                    # 独立静态 Web/PWA，保留现有视觉
contracts/                 # OpenAPI、目录清单与契约测试数据
launcher/                  # 玩家登录器
```

当前 `gm/internal` 不能直接由另一个 Go 模块导入。迁移使用明确的文件清单和来源摘要，在候选仓内完成包边界调整；不添加指向邻近游戏源码的相对依赖。当前游戏服务仍通过受版本约束的私有 API 协作，保留玩法服务与网关的独立发布。

实施依次完成：

1. 固定管理身份、能力声明、错误/分页、写入及目录契约；建立独立契约测试。
2. 把账号/角色和容器读取迁入网关管理模块，用独立 Web 客户端验证；复核玩家监听拒绝全部管理路径。
3. 以点券增减完成事务、幂等、回执、审计和刷新链；迁入邮件/福利，保留原规则 ID、资格快照及永久回执。
4. 迁入背包与任务操作；按需补游戏接口，完成客户端状态消费验证。
5. 输出分片 PVF 展示/校验包，替换常驻完整物品摘要和旧任务目录路径；加入有界后台任务。
6. 对等验证后从部署清单移除独立 GM 常驻服务；保留原服务及配置作回退，逐批迁移能力。

## 验收与资源指标

新增功能必须包含客户端关闭后任务继续、重复提交/响应丢失不重发、并发写冲突、数据库回滚、PVF 换代与旧游标失效、多端权限和管理路由隔离。

资源验收分别测量：空载网关、载入目录后、首次与连续查询、多管理员并发、后台批次及同时资源下载。记录进程 RSS/PSS、cgroup 内存与 swap/峰值、Go 堆、缓存字节、连接数、查询量和延迟。离线建索引单独测量。当前约 169 MiB 的 GM 预览工作集属于旧部署形态，不能当作新网关的验收数据。

同进程合并只减少一部分运行时与连接池开销；主要收益来自展示目录移至客户端、磁盘随机读取、移除全量构建回退以及限制请求和作业并发。具体内存目标在第一批迁移实测后确定。
