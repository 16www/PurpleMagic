# GM v1 接口与功能设计草案

2026-10-17当前接口以[源码提取的路由目录](API_CATALOG.md)为准，当前边界见[全局架构](ARCHITECTURE.md)。本文件保留设计背景；新管理入口位于单网关，GM Web独立分发，Hub与GM会话仍需统一。

状态：阶段四持续实现。单网关和独立 GM Web 已接分页查询、PVF 详情、邮件/福利/运营作业、点券流水、任务变更与物品操作。已孵化宠物增加成长详情及背包/穿戴关联删除，宠物装备增加期限修改和颜色记录联动删除；字段和事务见 [背包操作](GM_INVENTORY_OPERATIONS.md)。当前实现范围见 [单网关说明](GM_GATEWAY_IMPLEMENTATION.md)，其余目标见 [GM 功能清单](GM_FEATURE_MATRIX.md)。

## 当前已实现

- `GET /api/v1/capabilities`；账号列表、账号基础资料及其角色摘要；独立角色检索和单角色基础资料；物品分页。
- `inventory.read`、`mailbox.read`、`quests.read`：15 个资源容器、实例详情、邮箱分页/单封详情、角色任务状态及 PVF 任务目录。列表和详情分别读取；物品及任务分页绑定 PVF 代次。字段与离线索引用法见 [角色资源查询](GM_CHARACTER_RESOURCES.md)。
- 现有 GM Cookie 鉴权、统一响应、请求编号、禁止缓存、3 秒读取期限；列表默认 20、最多 100。签名游标绑定资源、条件及页大小。所有身份 ID 和物品堆叠上限使用字符串。
- 账号列表按注册表 ID 排序，当前页角色摘要每个配置分片只查一次基础表，不加载背包、装备、数值或钱包；角色检索独立分页，按角色 ID 的字节顺序合并分片。缺失表/读取失败返回 503，不伪装成空列表。
- 列表结果和内存分配有界；包含文字的模糊查询与二进制角色排序仍可能扫描数据，完整规模的查询计划/耗时尚需验证。超时取消会传递到数据库驱动。
- 工作台显式提交查询，空闲不轮询；切换时取消并丢弃旧成功/失败响应。角色在线状态当前固定为 `unknown`，读取账号状态仅表示原准入停用标记，不等同完整封禁管理。
- `mail.write`、`benefits.write` 和 `tasks.read` 根据事务、物品索引与存储依赖声明。写接口已实现会话 CSRF、创建幂等键、规则/任务版本与投递日志；实际路由、流程和限制见 [邮件、福利与任务契约](GM_OPERATIONS_V1.md)。`bans.write`、`dungeonRuns.read` 当前为 false，独立自动化管理凭据继续设计。

## 服务职责

GM 负责管理界面、分页查询、操作审计、任务、福利政策和邮件事务。游戏进程负责实际登录准入、在线会话和可信过图事件。网关负责玩家 HTTPS 入口、签名更新源和独立管理 Hub。GM 继续独立构建，不导入游戏服务内部包。

玩家公开网关保持明确路由白名单。管理接口由私有管理监听提供；浏览器通过已认证的同源 Hub 会话访问。服务间凭据保存在服务端配置中。浏览器写请求需要会话校验和 CSRF 防护；自动化客户端使用独立、可撤销并具名的管理凭据。旧 `/api/*` 页面兼容期与新 `/api/v1/*` 契约分别维护。

## 统一约定

- 所有 ID 使用字符串，避免浏览器整数精度问题。`accountId` 是权威账号键，`panelId` 是旧注册表自增键，二者独立命名；角色归属由后端校验。
- 时间使用 UTC RFC3339，显示时转换；列表响应带 `observedAt`。游戏 API 不可用时在线状态为 `unknown`，不能当作离线允许写操作。
- 普通成功返回 `data`、`requestId`；列表额外返回 `page: {limit, nextCursor}`。错误返回 `error: {code, message, retryable}`、`requestId`，使用实际 HTTP 状态码（400/401/403/404/409/429/503），不向浏览器传 DSN、凭据或 SQL。
- 列表默认 20、最大 100，游标绑定筛选条件与稳定排序，不做默认全量加载。列表只读必要列；钱包、背包、任务和邮件在用户打开相应详情时读取。跨账号/角色检索不能为每一行加载完整领域聚合。
- 输入文字不触发数据库请求；提交查询、分页或刷新时请求。筛选改变重置游标。账号/角色切换取消旧请求并核对请求序号与当前目标，丢弃旧成功和失败响应。
- 当前邮件任务同步保存预览并按每次最多 10 个目标推进，返回 `200`；前端主动刷新，空闲不轮询。长期后台作业的队列、调度和保留策略另行实现。
- 创建规则和预览要求幂等键，并绑定内容与目标；相同键不同内容返回 `409`。规则启停和任务推进要求准确 `revision`，重复旧版本返回 `409`。余额、物品和邮件继续走已有事务。幂等任务记录不替代永久福利回执。
- 修改政策、规则和封禁使用资源 `revision` 防止覆盖其他窗口。审计记录操作者、目标、理由、请求 ID、结果与时间，不记录密码/token。

## 目标路由

| 方法与路径 | 行为及边界 |
| --- | --- |
| `GET /api/v1/capabilities` | 返回已实现功能、版本和依赖可用状态；缺失功能不显示成可执行操作 |
| `GET /api/v1/accounts?q=&limit=&cursor=` | 账号分页摘要；显式筛选，不取所有角色完整聚合 |
| `GET /api/v1/accounts/{accountId}` | 单账号详情与各数据来源状态 |
| `GET /api/v1/accounts/{accountId}/characters` | 受账号角色数上限约束的摘要列表 |
| `GET /api/v1/characters?q=&limit=&cursor=` | 独立角色名或 ID 检索；基础摘要分页 |
| `GET /api/v1/characters/{characterId}` | 角色详情，返回权威所属账号 |
| `GET /api/v1/characters/{characterId}/inventory?container=&limit=&cursor=` | 已实现：指定容器的槽位摘要分页；账号金库取权威所属账号，数据库读取失败返回具名错误 |
| `GET /api/v1/characters/{characterId}/inventory/{container}/{slot}` | 已实现：当前持有物品实例与版本，链接 PVF 模板详情 |
| `GET /api/v1/characters/{characterId}/quests?state=&limit=&cursor=` | 已实现：active/completed/all 状态分页、角色进度与读取时刻；非空 q 当前返回 400 |
| `GET /api/v1/characters/{characterId}/quests/{questId}` | 待实现：任务说明、进度、前置条件、奖励及可用操作 |
| `GET /api/v1/quests?q=&kind=&limit=&cursor=` | 已实现：持久 PVF 任务目录查询，kind 匹配 PVF grade；当前角色可接资格待接 |
| `GET /api/v1/quests/{questId}` | 已实现：单条静态说明、前置关系、条件及奖励 |
| `GET /api/v1/characters/{characterId}/mailbox?limit=&cursor=` | 已实现：角色邮箱分页，与发放作业回执分别读取 |
| `GET /api/v1/characters/{characterId}/mailbox/{mailId}` | 已实现：指定角色的单封正文、金币、附件及领取状态 |
| `GET /api/v1/items?q=&kind=&limit=&cursor=` | 有界物品查询，kind 为 equipment/stackable；目录未准备时返回具名状态 |
| 邮件、福利、任务路由 | 已实现；以 [GM_OPERATIONS_V1.md](GM_OPERATIONS_V1.md) 为准 |
| `GET/POST /api/v1/bans` | 分页查询或建立账号/IP 封禁，包含理由、期限和执行范围 |
| `POST /api/v1/bans/{banId}/revoke` | 解除指定封禁并审计；其他有效封禁仍生效 |
| `GET /api/v1/dungeon-runs` | 按账号/角色/副本/时间段分页查通关过程与数据完整性 |
| `GET /api/v1/dungeon-runs/{runId}/events` | 查询有序、去重后的过程记录与服务端判定 |
| `GET /api/v1/anomalies` | 展示规则版本、证据、数据缺口与核查状态 |
| `POST /api/v1/anomalies/{id}/reviews` | 保存人工核查结论；当前设计不由异常命中自动封禁 |

网关更新源沿用已实现的 Hub 签名发布链。跨服务入口做明确适配，管理表单不直接向任意 URL 发送管理凭据。

## 一次性新手福利

已核验的旧实现将永久回执与邮件一起提交，回执在邮件领取/删除、进程重启或响应丢失后仍存在。现有规则按规则 ID、角色 ID、创建时间去重；删角重建会产生新资格。它不能直接等同于“每账号终身一次”。

每条规则明确选择每账号一次或每角色一次。账号级资格锁与回执落在账号维度，角色只决定投递目标；回执保存实际角色与邮件编号。当前候选沿用角色级删角重建视为新角色的语义；账号级不会因为重建角色恢复资格。不同福利包的独立性、资格起点及历史用户是否补发继续作为开放需求。

候选版已在旧管理页接入两种范围：手动账号级预览按槽位选一个有效收件角色；自动账号级发放投递至首个成功处理的符合条件角色。预览展示收件目标及历史实际投递目标，新规则默认停用。新增账号级规则/任务保存在独立表中，防止旧 GM 忽略 scope 后按角色重复发放。新 console 已通过 v1 接入创建、启停、预览、批次发放与回执分页。

迁移必须读取旧 campaign ID、signup 快照、永久回执和既有邮件关系，不能因为换前端或新建规则自动再次发放。领取与投递是两件事；邮件消失且没有领取证据时显示未知，不能解释为未发而自动补发。并发重试、事务回滚、发送后响应丢失、任务进度未保存、删角重建和旧回执迁移均需隔离数据库验证。

## 封禁执行

旧游戏管理 API 已支持账号 disable/enable/kick；停用会更新账号标记、撤销登录 token，并关闭登记在准入管理器中的连接。现有表没有期限、原因和封禁审计，也未发现用于登录准入的 IP 封禁规则。

新记录拟包含 `banId, subjectType, subject, scope, reason, startsAt, expiresAt, revision, createdBy, revokedAt`，永久封禁显式使用空到期时间。响应区分规则已保存与各执行点已生效，提供依赖故障和待同步状态。

账号规则必须由游戏登录/握手处权威执行；IP 规则需要分别覆盖玩家注册、登录和适用的游戏连接入口。HTTP 来源和游戏 TCP 出口可能不同，不能从历史登录 IP 推断游戏连接身份。只接受受信网关重写的来源信息，IPv4/IPv6 统一规范化。是否支持网段及在线立即断开作为具体运营选项，实施前明确。

这些能力需要游戏侧版本化适配；单独在 GM 数据库增加一条记录或仅在 HTTPS 网关拦截，不能宣称完成全部封禁。

## 过图与异常数据

现有 `game-dungeon-move-committed` 等日志包含副本、房间、地图、访问/清理状态及连接信息，但受 packet log 开关影响，缺少独立可靠的采集契约。日志可用于历史调查，不作为完整运营数据库。

在游戏权威状态提交点产生结构化事件：`eventId, schemaVersion, serverId, bootId, runId, sequence, accountId, characterId, dungeonId, mapId, kind, occurredAt, outcome`，并固定客户端/服务端/PVF 版本依据。区分进入、房间迁移、通关提交、结算提交、中断和拒绝事件；客户端请求或计时只作为注明来源的附加值。

采集采用有界持久缓冲和批量传送，GM 按事件 ID 去重；重启、重传、乱序、缺口和磁盘压力需要可观察状态。采集异常不能无限占用游戏堆内存或阻塞玩法；发生缺口时标记该局数据不完整。保留期限、索引和归档配额按数据量确定。

先做只读核查规则：非法迁移、重复结算尝试、异常耗时、状态与收益不一致。耗时/伤害阈值需要分职业、装备、副本、队伍和服务端版本验证；单条客户端上报或不完整事件流不能直接判定作弊。

## 实施顺序与验收

新增实验需求：[玩家资料公开快照](PUBLIC_PLAYER_SNAPSHOTS.md)。管理员可选择角色名单或全量公开，后者覆盖后续新角色。低优先级任务默认每日生成背包、穿戴与通关记录快照；外部 `/public/v1` 仅查询快照。此部分为待实现契约，与需要鉴权的管理 `/api/v1` 分开。

1. 完成 PVF 内存与旧页面竞态修正，记录 Linux 常驻/峰值/swap 和冷暖查询耗时。
2. 实现 v1 契约、能力声明、分页摘要查询及 console 只读适配；查询次数不随页面角色数量线性放大，空闲页不持续查询。
3. 按确认后的资格范围完善新手福利、预览和投递回执，验证旧数据迁移及隔离数据库并发/回滚。
4. 优先接入玩家背包/仓库、持有物品实例、邮箱和游戏任务；任务静态资料增加持久 PVF 索引，玩家状态使用数据库分页投影。按 [功能清单](GM_FEATURE_MATRIX.md) 补齐原工具已有的角色管理、资产和任务操作。
5. 实现游戏侧封禁适配和 GM 管理，再接结构化过图采集及核查界面；以背包投影和通关记录为来源实现实验性公开快照。
6. 联调全部能力后准备实际部署包、数据备份、兼容矩阵、回退和验收清单，进入第五阶段。

## 角色金币接口

单网关已接角色金币查询、增减/设置、签名预览与分页流水。金额使用十进制字符串，余额与永久回执同事务保存，细节见 [金币操作契约](GM_GOLD_OPERATIONS.md)。

## 角色容量接口

单网关已接主背包、装扮栏和个人仓库容量查询、批次扩容、签名预览及分页流水。定点字段与永久回执同事务保存，细节见 [容量管理契约](GM_CONTAINER_OPERATIONS.md)。

## 账号金库接口

单网关已接 `/api/v1/accounts/{id}/vault` 与 `vault-operations` 的预览、提交、分页流水。开通/扩容和金币变更可原子提交，使用账号级版本及永久回执；与角色金币、点券流水分开，详见 [金库操作契约](GM_VAULT_OPERATIONS.md)。

## 福利 PVF 核对接口

单网关已接福利规则 `pvf-preview`、`pvf-apply` 和 `pvf-history`：新旧物品定义、签名确认、永久回执和分页历史。保留原规则和发放身份，未完成作业采用已确认版本，见 [福利换版契约](GM_BENEFIT_PVF.md)。
