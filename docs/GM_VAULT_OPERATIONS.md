# 账号金库金币与容量

角色资料中的“账号金库”管理整个账号共享的金币、容量与 GM 操作流水。支持开通金库、扩容、增加金币、扣减金币、设置目标余额；容量和金币可一起预览、原子提交。管理操作不扣角色金币、点券或商城扩容费用。

## 当前游戏契约

| 内容 | 存储与范围 |
| --- | --- |
| 金库金币 | 账号元数据 `account_cargo_gold`，上限取当前 PVF 档位金币上限与 2147483647 的较小值 |
| 金库容量 | 账号元数据 `account_cargo_level`，单位为格；档位读取当前 PVF `etc/accountcargo.etc`，已核验配置为 1 和 8～240（每档 8） |
| 开通标记 | `account_cargo_created`；正常已开通金库的容量大于 0 |
| 金库物品 | `AccountInventory` 的 list 12，与角色个人仓库、共享晶块/灵魂区分 |

通过已有磁盘文件索引读取 `etc/accountcargo.etc`，文本使用已有有界缓存；每次只解析这一份小配置。六列升级记录给出容量、金币上限、材料、材料数量、金币费用与商城商品 ID。当前已核验 PVF 有 31 档、最高 240 格/4 亿金币；游戏购买流程的硬编码升级序列只到 120 格，但物品存储、移动及物品列表投影消费账号中实际容量。GM 管理档位使用 PVF，游戏购买流程另行适配。

预览绑定完整 PVF 摘要、该文件内容及解析版本形成的 `definitionRevision`。新增/移除档位、修改金币上限或更换 PVF 后，旧预览不能继续提交。结构缺失、重复档位、超出协议容量范围、损坏或格式变更返回明确错误。

游戏物品列表头能携带无符号 32 位金库金币，但存取确认包使用有符号 32 位整数。管理端同时校验 PVF 中所选档位的金币上限和两条协议均能表示的范围，金额在 JSON 中使用十进制字符串。现有余额超过新 PVF 档位上限时仍可读取，并以降低余额或提高容量的方式调整；超过协议上限的损坏存档返回错误。

未开通且缺失三个业务键时，按游戏的零余额/零容量表示；选择容量后创建元数据。扩容允许保持或提高容量。缩容需要先完成超出容量物品的迁移，不属于扩容接口。

## API

| 方法与路径 | 内容 |
| --- | --- |
| `GET /api/v1/accounts/{id}/vault` | 当前金币、容量、开通状态、各档金币上限和数据/PVF定义版本 |
| `POST /api/v1/accounts/{id}/vault-operations/preview` | 返回前后状态和签名预览 |
| `POST /api/v1/accounts/{id}/vault-operations` | 以原预览和请求编号提交，返回永久回执 |
| `GET /api/v1/accounts/{id}/vault-operations?limit=10&cursor=...` | 账号统一的分页 GM 金库流水 |

```json
{
  "gold": {"action": "add", "amount": "5000"},
  "capacity": 24,
  "revision": "<读取到的版本>",
  "definitionRevision": "<当前PVF定义版本>",
  "reason": "活动金库补偿"
}
```

`gold` 和 `capacity` 至少提供一个。金币动作是 `add`、`subtract` 或 `set`；增减数量须大于 0，设置支持 0。提交增加预览返回的 `planToken`，并提供 `Idempotency-Key`。两个 POST 均要求会话和 CSRF；十分钟签名绑定账号、全部参数、数据及PVF定义版本和操作者。

永久回执保存金币及容量的前后值、金币差额、原因、时间和操作者。同请求编号和原内容返回同一回执；内容改变则返回冲突。已提交请求的恢复在检查当前存档、PVF和在线状态之前完成，支持网络响应丢失、页面刷新及从同账号另一角色打开后恢复。

## 查询与事务

查询使用只读一致性事务，仅投影账号身份、更新时间和四个元数据键：金币、容量、开通标记、`gm_vault_sequence_v1`。单值最多 128 字节；其他账号元数据、物品和角色属性不进入此查询。页面按打开、刷新和翻页请求，静置不轮询。

写事务先锁账号行；重新读取权威版本后，按分片和角色 ID 对账号的有效角色列表做有界当前读取。写入前后逐个核对在线状态，只更新选中字段、更新时间与管理版本，保留点券、荣誉、代表账号名、其他元数据和玩家物品。

`account_vault_operations` 使用账号分片，与元数据变化共用事务。保存、后置在线检查或回执失败均回滚。显式 `--init-management-schema` 初始化该表，常规启动检查；新表不改变角色金币、点券或物品流水。

跨进程游戏编辑锁仍是上线前置项，用于覆盖在线采样后的登录竞争。原生客户端的开库、存取和重新进场展示在第五阶段验收。
