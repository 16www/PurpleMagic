# 在线角色邮件

“邮件与福利 → 在线角色”把首次预览时在线的角色固定为本次收件人。任务详情显示采集时间、人数、奖励及分页名单；确认后每次投递10人。角色在预览后离线仍接收邮件，后续上线的角色留到下一次发放。“新建在线发放”创建新的请求编号和名单。

## 网关接口

`POST /api/v1/mail/online-preview` 使用管理会话、CSRF 和 `Idempotency-Key`。请求字段为普通邮件的奖励、`options` 与 `pvfChecksum`，正文上限4KiB；收件人由游戏会话快照确定。附件能力、随机品级、期限和PVF一致性遵循 [邮件契约](GM_OPERATIONS_V1.md)。

首次创建在幂等事务内读取快照，核对完整性，再按每100个角色查询基础摘要；分片内使用参数化定点查询。角色缺失、已删除、归属无效或名单超限时，整次预览失败。空名单返回 `422 preview_unavailable`；无法取得完整游戏快照返回 `503 online_snapshot_unavailable`。

成功后保存角色ID、账号归属、创建时间、会话代次和奖励。任务摘要额外返回：

```json
{
  "recipientSource": {
    "kind": "online",
    "snapshotId": "0123456789abcdef0123456789abcdef",
    "observedAt": "2026-10-17T00:00:00Z",
    "count": 2
  }
}
```

同一键和内容返回原任务，包括响应丢失、网关重启或游戏接口失联后的恢复；更换内容返回409。投递沿用原账号/邮箱事务，再次核对归属、删除状态和创建时间，保存永久回执；已成功项不重复发放。

## 游戏运行时契约

私有管理 API v1 新增 `online_snapshot` 动作，使用既有 Bearer 凭据。响应的 `onlineSnapshot` 包含随机ID、锁内采集时间、`complete: true` 和 `members`；成员只有 `characterId` 与十进制字符串 `generation`。

游戏在现有会话锁内复制 canonical 角色绑定，解锁后排序。上限5000人；身份不一致、代次为0或超限返回失败，保留完整名单语义。网关仅对本动作允许最大512KiB响应，其他动作仍为64KiB。游戏侧读取现有会话索引，不新增数据库查询、常驻名单缓存或后台扫描；网关和网页按用户操作发起请求。

本接口适用于该游戏进程拥有全部角色会话的部署。若以后将在线会话分布到多个游戏进程，需要先定义实例集合及完整性聚合，才能提供跨实例全量名单。

游戏适配当前在独立候选中完成，接入时须合入实际累计游戏源码并验证。它只扩展私有管理接口，不依赖玩家 EXE 变化。角色资产编辑仍需另行完成游戏跨进程编辑锁。

## 验证

- 游戏处理器：认证、空/最大/超限名单、绑定替换、并发快照和竞态检测。
- 网关：最大响应和长度限制；一次性单/双分片MariaDB验证120人、100人摘要批次、同键并发、失败不建任务、失联恢复及12批投递。
- 网页：示例在线名单、丢失响应恢复、离线角色排除、确认发放、新建快照、手机与主题及空闲零请求。

数据库专项使用 `python gateway/scripts/test_mysql.py`；隔离预览启动后运行 `python scripts/verify_gateway_online_mail.py`。
