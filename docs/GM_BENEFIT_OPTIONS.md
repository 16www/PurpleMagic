# 长期福利附件参数

“邮件与福利 → 新建福利规则”支持每账号一次、每角色一次，以及自动覆盖首次启用后创建的角色。读取附件参数后，可设置品级、强化/增幅、锻造和有效天数；选项按当前PVF能力显示和校验。

规则保存的是发放选项。指定有效天数从每次实际投递开始计算；随机品级为每位收件人生成。普通邮件仍在预览时固定实例。有效天数为0沿用PVF默认期限。

## 保存与投递

`POST /api/v1/benefits` 的参数规则携带 `options` 和 `pvfChecksum`。字段和范围沿用 [邮件契约](GM_OPERATIONS_V1.md)，请求上限4KiB。首次保存校验物品、能力、PVF摘要和选项；重放同一请求返回原规则，读取当前PVF失败也可恢复已保存结果。

规则和作业的 `reward.deliveryPlan` 返回版本与选项，`pvfChecksum` 标记批准版本。规则中的附件保留静态属性，随机品级和指定到期时间在投递时生成。

投递在账号/角色/邮箱事务内完成以下步骤：

1. 读取永久回执；已有成功记录时返回原结果。
2. 核对角色归属、删除状态和创建时间。
3. 根据已批准规则与当前匹配PVF生成附件。
4. 保存邮件和包含实际附件、投递时刻的永久回执。

邮件领取或删除后回执继续保留。重复预览、手动补发、自动扫描、服务重启和响应丢失均复用同一去重身份。账号规则保存实际收件角色，角色规则按创建时间区分删角重建。未提交的事务失败后可重试；已提交的实例不重新随机或延长期限。

`GET /api/v1/tasks/{id}/recipients` 对已投递参数规则增加 `delivery.grantedAt`、`delivery.pvfChecksum` 和 `delivery.reward.attachments`。桌面表格和手机卡片展示实际属性与到期时间。自动发放后的结果也能通过该规则的新预览查询。

## 存储与兼容

新参数规则和作业分别进入 `<账号表>_benefit_v2_campaigns`、`<账号表>_benefit_v2_jobs`。网关合并分页读取新旧格式，旧游戏/GM读取原表时不会执行未展开的参数规则。原规则ID、表、奖励和历史去重身份保持。

升级时使用已有 `--init-management-schema` 初始化新增表，再启动网关；启动检查不自动建表。备份包含这些表及账号元数据。新参数规则由网关扫描器负责自动投递，旧游戏进程继续读取其原有规则。

扫描每轮读取一次规则列表；每次投递在共享规则锁内再次核对启用及资格，停用等待进行中的投递完成。参数规则的手动和自动发放都要求PVF摘要匹配。PVF换代后保留旧规则、任务与回执，并停止其新投递；通过[核对 PVF](GM_BENEFIT_PVF.md)确认新定义后，原规则与未完成任务继续使用同一发放身份。

## 验证

一次性单/双分片MariaDB覆盖两种去重范围、同键并发、旧PVF拒绝、无索引恢复、创建30天后仍从投递计期、自动新角色、停用/重新启用、删除邮件后的实例恢复及新旧规则分页。事务失败回滚沿用邮箱/账号边界并有专项验证。

运行 `python gateway/scripts/test_mysql.py`；隔离预览启动后，`python scripts/verify_gateway_benefit_options.py` 验证实际页面、丢失响应、逐人实例、重复预览、手机主题及空闲零请求。
