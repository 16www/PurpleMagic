# 背包与仓库操作

在“账号与角色”打开角色，进入“背包与仓库”。可逐格编辑、选择本页或勾选多个位置，配置共同属性或删除整格。填写原因后预览前后值，再提交；“物品操作记录”按角色分页查看结果。

预览与提交请求体上限64KiB，覆盖200格的位置、版本摘要和签名预览；数量上限在业务层再次校验。

| 范围 | 当前行为 |
| --- | --- |
| 角色背包、快捷栏、个人仓库 | 配置所选物品或整格删除，每批最多 200 格 |
| 账号金库 | 同一账号的角色共用，支持配置与整格删除；使用账号事务和流水 |
| 装备属性 | 随机或满品级、强化、增幅类型、锻造；可选项与上限按物品 PVF 定义返回 |
| 堆叠数量 | 仅堆叠物品，数量为 1 至 PVF 堆叠上限，最多 2147483647；同步实例行和已有数量别名 |
| 账号晶块、灵魂 | 全部 12 个固定槽，支持从零发放、修改、清空和再次补入；数量为 0 至 2147483647，0 清除持久记录 |
| 有效天数 | 按原物品期限能力设置，从预览时刻计算；未填写的属性保持 |
| 批量配置 | 网页显示所选物品共同支持的字段；接口逐件校验，任意一项失败整批回滚 |
| 身上穿戴 | 支持所选实例配置与删除，保存到装备表，记录归属角色；槽 26 接宠物关联删除，槽 27..29 接宠物装备关联事务 |
| 已孵化宠物 | 查询名称、等级、经验、饱食度、编号与出战状态；背包和穿戴宠物支持关联删除 |
| 宠物装备 | 背包删除、穿戴关联删除；具备期限的实例可调整有效天数，能力按当前 PVF 返回 |
| 未孵化宠物蛋 | 保留查询；关联管理操作继续接入 |

增幅类型不变时保留原增幅数值。随机品级在预览时固定，提交和重复请求返回相同结果。附魔、徽章、装扮属性、绑定及耐久修改继续补齐。

晶块与灵魂的固定槽始终显示，缺失记录显示数量 0。新建记录时按当前 PVF 读取对应资源定义，复用游戏物品行编码器；修改已有实例保留其他数据。确认框显示数量前后值。账号库存不存在时，查询和预览只读取，提交才创建库存。

账号资产变化保存在“账号物品记录”，从任意所属角色进入均可查看。角色个人物品记录独立保存。切换角色或容器时重新读取；旧版本提交返回冲突。每批资产属于同一种所有者，账号和角色资产分别提交。

穿戴装备沿用当前实例的 PVF 能力，支持品级、强化、增幅类型、锻造与期限；数量固定为一件。界面选择“身上穿戴”后编辑或勾选操作，结果保存在“物品操作记录”。修改属性保留原槽位、实例编号、克隆外观及游戏运行时记录。游戏重新读取穿戴记录时按其定义计算装备属性。

已孵化宠物在“宠物”或“身上穿戴”查看实例详情。选择删除后，预览列出宠物名称、等级、经验，以及是否清除当前出战关联。提交同时删除物品实例和对应成长存档；其他宠物、宠物装备、城镇显示偏好与其他宠物的通关成长回执保持。成长编辑、改名与宠物蛋操作继续适配。

## API

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/v1/characters/{id}/inventory/{container}/{slot}/options` | 获取当前实例、版本、PVF 摘要和配置能力 |
| `POST /api/v1/characters/{id}/inventory-operations/preview` | 生成逐格变更及签名预览，不保存物品或回执 |
| `POST /api/v1/characters/{id}/inventory-operations` | 原子提交并返回持久回执 |
| `GET /api/v1/characters/{id}/inventory-operations?limit=20&cursor=...` | 查询角色物品操作记录 |
| `GET /api/v1/accounts/{id}/inventory-operations?limit=20&cursor=...` | 查询账号金库与晶块/灵魂操作记录 |

配置预览示例：

```json
{
  "accountId": "<角色所属账号>",
  "action": "configure",
  "items": [{"container": "equipment", "slot": 9, "revision": "<实例版本>"}],
  "options": {"qualityMode": 0, "upgradeLevel": 12},
  "pvfChecksum": "<完整 PVF SHA256>",
  "reason": "装备修复"
}
```

`qualityMode` 为 0（随机）或 1（满品级）；其他可选字段为 `amplifyType`、`forgingLevel`、`expirationDays` 和十进制字符串 `count`。删除请求使用 `action: "delete"` 并省略 `options`。提交时保持原请求内容，加入预览返回的 `planToken`，另带 `Idempotency-Key`。POST 使用管理会话及 `X-CSRF-Token`。

账号金库使用 `container: "account-cargo"`，晶块/灵魂使用 `container: "shared"`；仍从所属角色路径预览及提交。`ownerScope` 返回 `account` 或 `character`。账号流水记录操作时所选角色，游标绑定账号；共享实例版本绑定账号、容器、位置、实例内容及记录是否存在。

共享列表、详情及预览的 `present` 区分固定槽定义和持久实例；不存在的槽为 `false`，实际存有数量 0 的记录为 `true`，两者版本不同。`quantity.min` 返回 `"0"`，普通堆叠物品为 `"1"`。清空后重放原已提交请求只返回原回执，不重新发放资源。新建资源需要完整 PVF 定义；错误的已有物品编号保持可见，提交时拒绝覆盖。

预览签名绑定账号、角色、位置、完整实例版本、操作参数、原因、管理凭据与 PVF 摘要，有效期 10 分钟。旧实例、过期预览或新请求使用旧 PVF 时返回冲突。普通实例原始行存在时须为已适配的 119 字节结构，且物品编号与记录一致；宠物穿戴使用专用结构与编号读取。

角色行锁内重验归属和实例版本，仅保存本次涉及的库存字段，回读结果后写入同事务回执。已提交请求先按原内容读取回执，PVF 换代或游戏接口暂不可用时仍可恢复。物品与任务使用独立流水表。浏览器在当前标签页保留待确认请求，刷新后可重试取得原结果。

账号资产先锁定账号和共享库存，再核对当前角色归属，整个账号库存与账号物品回执同事务保存。账号与角色在不同逻辑分片时仍使用同一 MySQL 事务。共享槽核对现有领域规则中的固定物品映射；角色中遗留的账号槽副本保持，查询继续只使用账号存档。

穿戴使用 `container: "equipped"`，`ownerScope` 为 `character`。当前游戏穿戴槽为 0..32；槽 26 使用宠物关联事务，槽 27..29 同步宠物装备存档，`pet-equipment` 管理背包宠物装备。穿戴、角色背包和个人仓库可在同一角色批次提交，任一保存或回执失败均回滚；只改普通穿戴时不加载或创建背包。存储适配保留原装备行键，重复槽位记录拒绝修改，背包中遗留的穿戴副本保持。

宠物详情及 options 附加 `pet` 和 `relatedRevision`。删除 `pets` 或 `equipped/26` 时，每个选择同时提交 `revision` 与 `relatedRevision`；后者绑定可见成长数据、出战指针及存档更新时间。缺失或错位关联返回 `petLinkError`，options 的 `canDelete` 为 false；重复编号或坐标在事务内拒绝。详情只读取所选位置的有界成长投影，不加载所有宠物、原始行、装备或通关回执。

宠物操作按背包、穿戴、宠物顺序加锁，复用游戏编号解析，核对物理位置与成长记录。当前穿戴构造器生成 47 字节，另兼容已有 43 字节摘要；权威编号位于 +24。删除和成长存档保存及管理回执在同一事务，回读后提交。宠物成长变化使旧预览失效；相同已提交请求重放返回原回执。

宠物装备背包范围为 `pet-equipment/140..188`，穿戴槽 `27/28/29` 对应红/蓝/绿。背包实例独立保存；穿戴实例同时维护 `Pet.Artifacts`，详情/options 返回 `petArtifact`、`relatedRevision`。关联版本覆盖所选颜色的完整持久内容和父存档更新时间，提交时重新验证与游戏投影一致。错误关联返回 `petArtifactLinkError`；不自动覆盖错误记录。

穿戴宠物装备配置使用既有 PVF 能力，当前具备期限的实例可调整有效天数。配置后通过游戏同一投影函数同步原始行及附加字段；删除同步移除颜色记录。可与背包、普通穿戴及已孵化宠物删除组合为一个角色事务，保留其他颜色、成长存档与出战状态。查询仅读取所选颜色，原始行限制4KiB，附加字段最多256项、每项4KiB。

## 安装与验证

管理表通过显式安装入口创建：

```text
PlayerGateway --config gateway.json --init-management-schema
```

角色物品表为 `inventory_management_operations`，账号物品表为 `account_inventory_management_operations`；已有任务与点券表保留。签名绑定密码及登录 Key 摘要，升级后旧物品流水游标需从第一页重新读取。

当前保存前后查询游戏在线状态；账号资产核对该账号所有角色。上线前还需游戏端跨进程编辑锁，覆盖检查后立即登录的竞争窗口。

验证覆盖单／双分片 MariaDB、200 格批次、并发重放与版本竞争、失败回滚、随机品级一致、数量原始行同步、签名篡改／过期／旧 PVF 拒绝和回执恢复。实际网关浏览器覆盖配置、批量删除、数量、刷新恢复、任务流水隔离、静置零请求、深浅主题与移动布局。游戏内重新登录后的原生表现留待上线验收。

```text
python gateway/scripts/test_mysql.py
python scripts/verify_gateway_inventory.py
python scripts/verify_gateway_account_inventory.py
python scripts/verify_gateway_shared_resources.py
python scripts/verify_gateway_equipped.py
python scripts/verify_gateway_pets.py
python scripts/verify_gateway_artifacts.py
```

共享资源另覆盖单／双分片的首次创建与回执失败回滚、两角色同时补入空槽、12 槽原子初始化、缺失与零数量记录版本冲突、数量越界及 PVF 定义缺失拒绝；浏览器覆盖清空后重放不重发、再次补入和跨角色读取。

穿戴另覆盖单／双分片的 HTTP 预览/提交/重放、空附加字段版本、原始行与外观数据保留、同版本并发、混合背包/仓库批次回滚、后置在线变化回滚及重复槽位拒绝。浏览器验证配置、重载读回、删除、角色流水与背包保持。

宠物另覆盖单／双分片的成长版本冲突、背包与出战宠物联合删除、成长保存和回执失败回滚、物理编号重复及并发竞争。游戏穿戴构造器回归核对专用行和编号；错误坐标、缺失成长记录及重复关联均拒绝。网页验证详情、关联删除预览、重放、重载、流水、其余宠物保持和出战指针清除。

宠物装备另覆盖游戏Move产物与管理投影一致、单／双分片期限联动、背包独立修改、关联版本冲突、错配拒绝、混合宠物批次及末尾失败/后置在线回滚、并发只成功一次。网页核对颜色记录、期限前后值、双颜色删除、其他宠物保持、回执重放与分页流水。
