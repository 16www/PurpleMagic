# 转职与觉醒

角色详情的“转职与觉醒”页签支持选择基础职业、转职分支和一/二次觉醒。选项来自当前 PVF 的实际职业段；转职、一觉、二觉分别要求15、50、75级。相同名称的职业附编号区分。

预览展示职业、技能点、技能等级、24项基础属性及职业任务的变化。提交后可查询独立历史；响应丢失时，刷新页面可重试原请求取得永久回执。

## 变更规则

- 改变基础职业、转职分支或降低觉醒阶段：按目标 PVF 重建免费技能及快捷栏，清除技能冷却，返还已消耗的 SP/TP。PVF 下调基础点数时，以新总量完成重置。
- 同分支提高觉醒阶段：保留已学技能、快捷栏第二页、冷却与点数消耗，补充对应觉醒的免费技能。新总量不足以覆盖已消耗点数时返回错误。
- 属性沿用游戏职业成长算法及 HP/MP 兼容加值，保持等级和累计经验；额外 SP/TP、金币、背包、点券及其他角色字段保留。
- 对应职业任务标为完成；新任务带管理操作标记。普通任务、副职业任务、既有奖励元数据及旧职业完成记录保留。预览列出保留的旧阶段记录，任务奖励仍由原任务结算流程管理。
- 提交时核对角色离线，按角色→技能→任务的顺序取得父行锁。角色、技能、任务状态与管理回执在同一数据库事务中提交。

## 接口

所有接口位于独立管理监听，复用登录鉴权；POST使用CSRF令牌。

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `/api/v1/characters/{id}/profession` | 当前职业、点数、版本及职业选项 |
| POST | `/api/v1/characters/{id}/profession-operations/preview` | 变更预览及10分钟有效的签名令牌 |
| POST | `/api/v1/characters/{id}/profession-operations` | 按 `Idempotency-Key` 提交或恢复原回执 |
| GET | `/api/v1/characters/{id}/profession-operations` | 独立分页记录 |

预览请求包含 `accountId`、`targetJob`、`targetGrowType`、`revision`、`pvfChecksum` 和 `reason`。成长值低四位为转职分支、高四位为觉醒阶段。提交增加预览返回的 `definitionRevision`、`planToken`。

版本包含角色成长、完整技能账本和职业任务投影。定义签名绑定PVF摘要、索引清单摘要、目标属性与任务集合。旧版本提交返回冲突；已有回执优先恢复，可在PVF或游戏运行接口暂不可用时读取。

`<前缀>_profession_management_operations` 为新增回执表，通过现有 `--init-management-schema` 初始化及启动检查。任务写入只更新对应行的完成状态、进度与时间；既有奖励字段和额外元数据原位保留。

## PVF 索引

网关构建包包含独立的 `GMIndex` 工具（Windows为 `GMIndex.exe`）。已有物品摘要及PVF目录索引放在同一索引目录后执行：

```text
GMIndex --pvf <Script.pvf> --sha256 <完整SHA256> --directory-index <pvf-directory.bin> --item-index <items.json>
```

工具离线编译职业和技能定义、职业任务子集，逐记录读回验哈后原子安装 `professions-v1-<SHA256>.bin`。任务索引可复用已有代次。相同内容再次执行只校验复用，导入进程完成后退出。

网关仅加载小清单、职业任务子集与当前选中的一个职业技能表。切换职业替换技能缓存；PVF摘要变化时丢弃旧缓存，读取对应的新索引。新PVF应先离线生成索引，再切换网关配置。缺少新代次索引时，职业功能返回不可用状态。
